# Ruleset payloads

These are [repository ruleset request payloads](https://docs.github.com/en/rest/repos/rules#create-a-repository-ruleset) and [organization ruleset request payloads](https://docs.github.com/en/rest/orgs/rules#create-an-organization-repository-ruleset). Committing them does not change GitHub settings. Required workflows need organization support for the `workflows` rule; if unavailable, retain operator-only merges. See [supported required-workflow events](https://docs.github.com/en/enterprise-cloud@latest/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets#supported-event-triggers).

`public-repo.json` protects `main`: no deletion or force pushes, squash PRs only, an approving CODEOWNER review of the latest push, resolved conversations and the `checks` status from GitHub Actions (15368). CODEOWNERS retains `@vibecoddingops`; bot review is supplementary. Organization admins have a `pull_request` bypass so the operator can merge their own PRs without self-approval. Limit that role to trusted operators. The bypass requires a PR but can bypass review and checks; operators should still wait for checks and resolve conversations. A numeric review count cannot enforce two distinct reviewing bots.

`org-release-notes-gate.json` adds the public repository's required release-notes workflow. Its selector includes only `software-factory` on `main`; its source repository ID is `1472948871`. The workflow path and full SHA bind the trusted implementation. The pinned commit contains the implemented gate and its regression tests. Publish that commit before applying the payload; preserve it when merging this branch, or repin to a reviewed published commit containing the same workflow. Repin after reviewing any workflow change. Do not substitute a mutable ref or a bare `release-notes-gate` status context: unrelated workflows use the same Actions integration and could forge that status. The status remains informational. The gate also fails every PR that changes `.github/workflows/**`, including deletions and renames, so these changes require operator bypass. Only organization admins have a PR-only bypass of this workflow requirement.

The gate uses `pull_request_target` restricted to `main`, checks out `github.sha` (trusted default-branch code), and reads PR content only as API data. It compares tracked versions against current main, regardless of author. Required-workflow rules ignore event filters, so both the workflow job and script guard default-branch targets; the script posts no statuses or labels for other targets. Install the public branch and organization workflow payloads together before allowing agent merges. Reopen existing PRs or push a new commit to trigger newly required workflows.

`public-release-tags.json` is a **disabled template** protecting `refs/tags/v*` against creation, update and deletion. Replace the Team `actor_id: 0` with a dedicated organization's release-actor team ID whose sole member is the machine user owning `RELEASE_PLEASE_TOKEN`, then set enforcement to `active`. Release Please creates tags with that token in `.github/workflows/release.yml`; the asset-upload `GITHUB_TOKEN` is not the tag actor. The only other bypass is the operator's OrganizationAdmin role, using `always` because tags have no PR path. Do not grant the shared Actions app (15368), Renovate, general write roles or agent accounts a bypass. Restrict release-token use to the reviewed release workflow. The release actor and operator must create version tags only at reviewed main commits; these rules restrict actors, not tag ancestry. Activate this tag protection before instances consume `github-tags` updates. Actions and instance-ref majors are labelled `needs-operator`; only digest, pinDigest, patch and minor updates can receive `agent-merge`.

`instance-repo.json` and `org-merge-gate.json` are also **disabled templates**. WP5 implements `hosting/paperclip-hermes/bootstrap/sf-bootstrap.sh rulesets [--apply]`; no settings writer is shipped here. Keep these templates disabled until the operator configures the instance and gate. Do not activate the instance branch template by itself: ADR 0001 excludes `ph-*.yml` callers from instance CODEOWNERS, so the org-required gate must protect them, or the operator must merge every caller change.

Before enabling `org-merge-gate.json`, replace `repository_id: 0` with the public source repository's numeric ID, the all-zero SHA with a **tagged release commit containing the implemented instance gate**, and the `sf-instance-*` selector with the intended instance names. Keep the source repo outside that selector. The `workflows` rule binds workflow path, source repository and SHA; a same-named check in a PR cannot satisfy it. Never substitute a mutable ref or a status named `sf-merge-gate`.

The WP5 apply command must default to dry-run, reject active unresolved placeholders, create or update by name, and read back every full payload for comparison. Endpoints:

| Payload | Endpoint |
| --- | --- |
| `public-repo.json`, `public-release-tags.json` | `repos/agenticcodingops/software-factory/rulesets` |
| `instance-repo.json` | The instance's `repos/OWNER/REPO/rulesets` |
| `org-release-notes-gate.json`, `org-merge-gate.json` | `orgs/agenticcodingops/rulesets` |

Do not POST organization payloads to a repository endpoint. An authenticated operator applies these settings; local CI does not apply or verify live enforcement.

For acceptance, list each endpoint, then fetch each managed ID at `ENDPOINT/ID`. Compare committed fields after removing server metadata (`id`, timestamps, source and links), sorting unordered rule/condition arrays and accounting for documented API defaults. A list response is only a summary and cannot establish payload equality. Verify the release team membership separately and test that an agent cannot create, replace or delete a `v*` tag, while the release actor can create one at a reviewed main commit. Verify a forged `release-notes-gate=success` does not satisfy the required workflow after the real gate fails. This apply/readback acceptance remains an operator step.
