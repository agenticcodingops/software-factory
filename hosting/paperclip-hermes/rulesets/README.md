# Ruleset payloads

These are [GitHub REST ruleset request payloads](https://docs.github.com/en/rest/repos/rules#create-a-repository-ruleset), with an [organization payload](https://docs.github.com/en/rest/orgs/rules#create-an-organization-repository-ruleset) for the merge gate. They live here to follow ADR 0001's public repository layout.

`public-repo.json` protects `main`: no deletion or force pushes, squash PRs only, an approving CODEOWNER review of the latest push, resolved conversations and the `checks` status from the GitHub Actions integration (15368). CODEOWNERS retains `@vibecoddingops`; bot review is supplementary. Organization admins have a `pull_request` bypass so the operator can merge their own PRs without self-approval. This role applies to all organization admins: keep its membership limited to trusted operators. The bypass requires a PR and can bypass this ruleset's review and status requirements; operators should still wait for successful checks and resolve conversations. Everyone else must obtain the required code-owner approval. See the [GitHub ruleset API's bypass actor and mode definitions](https://docs.github.com/en/rest/repos/rules#create-a-repository-ruleset). A numeric review count cannot enforce two distinct reviewing bots. The broader bot review policy and the gate implementation belong to later work packages; WP1 uses the operator approval path.

`instance-repo.json` and `org-merge-gate.json` are **disabled templates**. WP5 implements `hosting/paperclip-hermes/bootstrap/sf-bootstrap.sh rulesets [--apply]`; no settings writer is shipped in WP1. Keep both templates disabled until the operator configures the instance and gate. Do not activate the instance template by itself: ADR 0001 excludes `ph-*.yml` callers from instance CODEOWNERS, so the org-required gate must protect them, or the operator must merge every caller change.

Before enabling the org template, replace `repository_id: 0` with the public source repository's numeric ID, the all-zero SHA with a **tagged release commit containing the implemented gate**, and the `sf-instance-*` repository selector with the intended instance names. Keep the source repo outside that selector. The `workflows` rule binds the workflow path, source repository and SHA; a same-named check in a PR cannot satisfy it. Never substitute a mutable branch ref or add a status check named `sf-merge-gate` as a replacement. If the organization cannot enforce required workflows, retain the operator merge path.

The WP5 apply command must default to dry-run, reject active unresolved placeholders, create or update by name, and read back each full payload for comparison. An operator applies the public payload at `repos/agenticcodingops/software-factory/rulesets`, the instance payload at the instance's repository endpoint, and the org payload at `orgs/agenticcodingops/rulesets`. Do not POST all three to the public repository.

For acceptance, list with `gh api repos/agenticcodingops/software-factory/rulesets`, then fetch each managed ID with `gh api repos/agenticcodingops/software-factory/rulesets/ID`. Compare the fields in the committed JSON after removing server metadata (`id`, timestamps, source and links), sorting unordered rule/condition arrays and accounting for documented API defaults. The list response is only a summary and cannot establish payload equality. Repeat at the instance and org endpoints. This apply/readback acceptance requires an authenticated operator and remains unverified in WP1.
